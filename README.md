# CLI проекта

CLI — это управление проектом командами в терминале. Вместо длинных команд
Docker можно писать короткие: up, down, status, logs, check.
Файл cli.py вызывает Docker Compose. Он работает с контейнерами, описанными
в файле compose.yaml, и не зависит от того, выбран Groq или локальная модель.

## Сначала посмотреть команды

Нужен Python 3.10 или новее. Откройте терминал в папке с cli.py:

```sh
python cli.py --help
```

Эта команда показывает справку и ничего не запускает.

## Когда будет готов Docker Compose

Поместите cli.py в корень проекта рядом с compose.yaml. Установите Docker
с Compose plugin. Затем можно выполнять:

| Команда | Что делает |
|---|---|
| python cli.py check | Проверяет конфигурацию Compose |
| python cli.py up | Собирает и запускает контейнеры в фоне |
| python cli.py status | Показывает состояние контейнеров |
| python cli.py logs | Показывает последние строки логов |
| python cli.py logs -f | Следит за логами до Ctrl+C |
| python cli.py down | Останавливает контейнеры |

Можно указать папку проекта отдельно:

```sh
python cli.py --project-dir "путь/к/проекту" status
```

up пересоздаёт контейнеры проекта вместе. Это применяет изменения к запуску
и позволяет сохранить общую сеть контейнеров, если она понадобится.
Возможна короткая пауза. down не удаляет именованные тома с данными.
check проверяет формат Compose; доступ к модели и базе проверяется отдельно.
Если Docker сообщает об ошибке, CLI возвращает его код ошибки.

## Как устроен файл

1. build_parser описывает команды и подсказки для --help.
2. find_compose_file ищет файл конфигурации в папке проекта обычным циклом.
3. get_command_args выбирает аргументы Docker через if/elif.
4. main соединяет эти части, запускает Docker и обрабатывает ошибки.

Используются только встроенные библиотеки Python:

- argparse — разобрать команду из терминала;
- pathlib — работать с путями к файлам;
- subprocess — запустить Docker;
- sys — передать код завершения и вывести сообщения об ошибках.

Например, python cli.py status находит compose.yaml и вызывает Docker Compose
с командой ps --all. В терминале появляется список контейнеров проекта.

## Обработка ошибок

Если Compose-файл не найден, CLI подскажет, куда положить файл или как
указать --project-dir. Если Docker не установлен, появится сообщение об этом.
Если установлен Docker, но не запущен его движок или отсутствует Compose plugin,
ошибку покажет сам Docker. Ctrl+C прекращает просмотр логов, контейнеры при этом
продолжают работать. Для их остановки нужна команда down.

Успешный check подтверждает корректность конфигурации. Работа самого бота
проверяется отдельно по логам и ответу на сообщение в Telegram.

Проверены синтаксис, справка, сообщения при отсутствии Compose/Docker и
передача аргументов/результата процесса. Реальные контейнеры не запускались.
